# Ponder Integration for Scaffold-ETH 2

## Prerequisites

This skill assumes a Scaffold-ETH 2 project (`packages/nextjs/scaffold.config.ts` exists). If it isn't one, follow https://docs.scaffoldeth.io/SKILL.md to scaffold it first.

## Overview

[Ponder](https://ponder.sh/) indexes contract events into a database and serves them over GraphQL and SQL. You run and host the indexer yourself (centralized), unlike a subgraph on The Graph's decentralized network. It goes in a new workspace, `packages/ponder/`, whose config reads `deployedContracts` and `scaffold.config` from the nextjs package, so it indexes whatever `yarn deploy` produced without copying ABIs or addresses.

This skill covers the SE-2 glue; for the rest, see the [Ponder docs](https://ponder.sh/docs/get-started). `npm create ponder@latest -- --template empty` (in a temp dir) gives the current official boilerplate: start from its files and apply the SE-2 changes below.

## Workspace Setup

If the root `package.json` lists its workspaces explicitly (as the SE-2 repo does), add `packages/ponder` there. Projects created with `create-eth` use `"packages": ["packages/*"]`, which already picks it up.

Write `packages/ponder/package.json` without the template's dependencies: they pin versions that SE-2's Yarn age gate (`npmMinimalAgeGate`) can reject, and `yarn add` below picks versions that fit the repo.

```json
{
  "name": "@se-2/ponder",
  "version": "0.0.1",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "ponder dev",
    "start": "ponder start",
    "db": "ponder db",
    "codegen": "ponder codegen",
    "typecheck": "tsc"
  }
}
```

Then install from the repo root (Ponder requires Node.js >= 22.12):

```bash
yarn install
yarn workspace @se-2/ponder add ponder hono viem
yarn workspace @se-2/ponder add -D typescript@<version in packages/nextjs/package.json> @types/node@^22
```

The template's `ponder-env.d.ts` is regenerated by `ponder dev` / `ponder codegen`; commit it as is.

Add root scripts that forward to the workspace (`"ponder:dev": "yarn workspace @se-2/ponder dev"`, and likewise `ponder:start`, `ponder:codegen`, `ponder:typecheck`).

### tsconfig: resolve the `~~` alias

`deployedContracts.ts` imports a type through the nextjs `~~` alias. Without these two options `tsc` fails on it and the contracts are typed as `unknown`, so typos in event names or `event.args` go unnoticed:

```jsonc
// packages/ponder/tsconfig.json
{
  "compilerOptions": {
    // ...the Ponder template's options
    "paths": { "~~/*": ["../nextjs/*"] },
    "jsx": "preserve" // that import pulls in .tsx files
  }
}
```

### Environment variables

`packages/ponder/.env.local` (mirror the keys in a `.env.example`):

```env
# RPC for the indexed chain; falls back to the local chain (http://127.0.0.1:8545)
PONDER_RPC_URL_{chainId}=
# Optional: Postgres for production. Without it, Ponder uses PGlite (embedded) in .ponder/
DATABASE_URL=
```

## ponder.config.ts — Bridging SE-2 and Ponder

This indexes every contract deployed on the first target network. Adapt it to the project (e.g. several networks, or only some contracts):

```ts
// packages/ponder/ponder.config.ts
import { createConfig } from "ponder";
import { hardhat } from "viem/chains";
import deployedContracts from "../nextjs/contracts/deployedContracts";
import scaffoldConfig from "../nextjs/scaffold.config";

const targetNetwork = scaffoldConfig.targetNetworks[0];

const deployedContractsForNetwork = deployedContracts[targetNetwork.id];
if (!deployedContractsForNetwork) {
  throw new Error(`No deployed contracts found for network ID ${targetNetwork.id}. Run \`yarn deploy\` first.`);
}

const chains = {
  [targetNetwork.name]: {
    id: targetNetwork.id,
    rpc: process.env[`PONDER_RPC_URL_${targetNetwork.id}`] || "http://127.0.0.1:8545",
    // The local chain restarts from block 0, so don't cache its RPC data between runs
    cacheRpcRequests: targetNetwork.id !== hardhat.id,
  },
};

const contracts = Object.fromEntries(
  Object.entries(deployedContractsForNetwork).map(([contractName, contract]) => [
    contractName,
    {
      chain: targetNetwork.name,
      abi: contract.abi,
      address: contract.address,
      // Written by `yarn deploy`; keeps Ponder from scanning a live network from genesis.
      // If it's missing for a contract on a live network, set the block manually.
      startBlock: contract.deployedOnBlock ?? 0,
    },
  ]),
);

export default createConfig({ chains, contracts });
```

## Schema, Handlers and API

- **Schema** (`ponder.schema.ts`): one `onchainTable` per entity ([schema docs](https://ponder.sh/docs/schema/tables))
- **Handlers** (`src/*.ts`): `ponder.on("ContractName:EventName", ...)` from `ponder:registry`, writing with `context.db.insert(table)`. Event names and `event.args` are typed from the `deployedContracts` ABIs
- **API** (`src/api/index.ts`): keep the template's Hono app, which serves GraphQL at `/` and `/graphql` and SQL at `/sql/*`

## Frontend

Query the GraphQL API at `NEXT_PUBLIC_PONDER_URL` (default `http://localhost:42069/graphql`) with `fetch` + TanStack Query, both already in SE-2. What differs from a plain GraphQL API:

- each `onchainTable` gets a pluralized query (`greeting` → `greetings`) returning `{ items, pageInfo, totalCount }`, with `where`, `orderBy`, `orderDirection`, `limit` and cursor pagination
- `bigint` columns arrive as strings
- GraphQL errors arrive with status 200, so check `errors` before reading `data`

**Alternative:** [`@ponder/react`](https://ponder.sh/docs/query/sql-over-http) (`usePonderQuery`, built on TanStack Query) queries the `/sql/*` endpoint with Drizzle-style typed queries and live updates. It needs the Ponder schema importable from the nextjs package (e.g. `import * as schema from "../ponder/ponder.schema"`).

## Local Development Notes

**Stale data after restarting the chain.** `yarn chain` starts from block 0 each time. If Ponder shows stale data or errors after a chain restart + redeploy, stop it and delete `packages/ponder/.ponder/`.

**Harmless local warnings.** On the local chain Ponder logs `No new block received within expected time` (Hardhat/Anvil only mine when there are transactions) and `Detected public RPC URL`. Both can be ignored in development.

## Done When

With `yarn chain` running and contracts deployed, run each check and report what you saw:

1. `yarn ponder:typecheck` passes, and fails if an event name in a handler is misspelled (proves the `~~` alias resolves)
2. `yarn ponder:dev` indexes the local chain without errors
3. After a transaction that emits an indexed event (e.g. `setGreeting` from the Debug Contracts page), the GraphQL query returns the new row
4. With `yarn start`, the frontend page shows the indexed data

## Production

- Set `PONDER_RPC_URL_{chainId}` to a production RPC and `DATABASE_URL` to a Postgres database
- Run `ponder start` (with `--schema <name>`, or the `DATABASE_SCHEMA` env var, for zero-downtime redeploys)
- Point `NEXT_PUBLIC_PONDER_URL` to the deployed Ponder URL
- See the [Ponder deployment docs](https://ponder.sh/docs/production/self-hosting)
